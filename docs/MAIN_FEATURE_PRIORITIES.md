## 控制每批范围

1. 用户指定B3→B4→B2；B3核心已交付r7；r9完成B4客户端桥与B2核心。B4正式内容服务保留依赖，r10已接续B1历史核心，随后进入B5。模型识别/发送、隐私或数据正确性的实际阻断仍即时修复。
2. B2分两次可交付增量：语义MERGE与预算；Lifecycle周期调度。B3/B4也按各领域已有契约逐条完成用户操作，不等待所有管理命令都实现。
3. 每个功能增量包含必要的真实状态、关联标识、耗时与失败记录；全链路时间线和开发者模式属于核心能力。B5指补全跨所有worker的覆盖，不表示前面可以交付无法定位故障的功能。
4. 各批按影响范围做测试、核对必要界面、冻结并交付匹配安装包；安装验收只覆盖该批新增链路和关键回归。已通过且未受影响的专项不重复启动无限验收。
5. 当前r6的审核事务、提交后传播和真实Windows凭据库样本作为基线保留。已完成项只在回归、依赖修改或新证据显示风险时重开；隐私泄露、数据丢失或身份串用可中断上述顺序优先修复。
6. 不给无依据的工期或完成百分比。每次交付必须说明新增可用行为、实际验证和有限剩余项；本次仅调整计划，不新增实现或测试通过声明。
